# 手动测试清单（键盘 v2 + 步骤序列）

AI 负责桌面回归（`tools/` 七套）与 adb 冒烟；本清单是你手测的逐项步骤。
每项含 **步骤** 与 **预期**，测完可按极简格式反馈（如「A1 ✓ A2 ✗ 步骤3时光标没动」）。

## 准备（一次性）

1. 安装最新 debug 版（当前已装；若重装）：
   `adb install -r -d app/build/outputs/apk/debug/app-debug.apk`
2. 启动应用，等本地会话就绪（出现 shell 提示符）。
3. 术语约定：**键条** = 屏幕底部常驻一行（CTRL ALT ESC TAB ^C ←↑↓→ ⌨ ⛶）；
   **辅助键盘** = 点 ⌨ 后展开的多行键区（含绿色描边的 ⌨ ⛶ ＋）。
4. ⚠️ 注意：`^D` 会结束 shell（会话退出）、`^\` 发 SIGQUIT——测这两键前
   先想清楚，或放到最后测（会话可从菜单重建）。
5. 会话 shell 由发行版 `/etc/passwd` 决定：Debian 容器 root → `/bin/bash`
   （readline，方向键/HOME/^A 等行编辑可用），Alpine → busybox ash（自带行编辑）。
   若 passwd 指向的 shell 缺失则回退 `/bin/sh`（可能无行编辑，此时方向键会字面
   回显 `^[[D` 等——先输 `bash` 再测）。

## A. 辅助键盘

### A1 键盘开合 + 长按菜单
- **步骤**：
  1. 点 ⌨ → 辅助键盘展开；再点 ⌨ → 收起；
  2. 展开后观察：固定区（HOME…INS、F1–F12）在上两行，⌨ ⛶ ＋ 为绿色描边；
  3. 辅助键盘收起状态下，**长按 ⌨ 约 1 秒** → 应用菜单弹出；
  4. 点菜单外任意处收起菜单。
- **预期**：开合即时；菜单完整可见（底边不超出屏幕——这是修过的 bug：
  ⌨ 在屏幕底部、系统键盘没弹出时菜单曾整窗落到屏幕外）。

### A2 固定区编辑键 / F 键
- **步骤**：
  1. 在提示符输入 `echo 123456`（先不回车）；
  2. 按 ← 三次（键条方向键），再按 HOME → 光标应到行首；
  3. 按 END → 光标到行尾；回车执行；
  4. 输入 `vim` 回车进入 vim，依次按 PGUP / PGDN 翻页，DEL 删字符，
     F1 呼出 vim 帮助（`:h`），`:q` 退出。
- **预期**：HOME/END/PGUP/PGDN/DEL/INS/F1–F12 全部行为正确。

### A3 默认键集手感（控制符 + 符号）
- **步骤**（均在 bash 提示符下）：
  1. 输入 `echo abcdefg`，按 ^A → 光标到行首；^E → 行尾；
  2. 按 ^U → 整行清空；
  3. 输入 `echo hello`，按 ^W → 删掉一个词；
  4. 按 ^R → 出现反向搜索提示，输入 `ec` 能搜到历史，回车执行；
  5. 按 ^L → 清屏；
  6. 输入 `ls | wc -l`（| 与 > 用辅助键盘符号行打）→ 正常执行；
  7. 输入 `echo x > /sdcard/mt.txt` → 建文件成功（> 重定向生效）。
- **预期**：控制符逐个正确；符号可直接输入不翻输入法符号页。
- **反馈重点**：哪个键手感/行为不对，直接点名。

### A4 与系统输入法组合
- **步骤**：
  1. 点终端空白处 → 系统输入法弹出，输入中文（如「你好」）；
  2. 不收输入法，点 ⌨ → 辅助键盘展开，**输入法保持弹出**（组合设计——
     打中文时 ESC/CTRL/符号键随取随用，Termux 同款形态）；
  3. 按一个符号键（如 `|`）→ 字符进终端；
  4. 再点终端 → 输入法收起（点终端=输入法开/关）；再点终端 → 输入法回来，
     字母数字正常打，辅助键盘全程不动。
- **预期**：两套键盘共存不抢焦点、互不残留；只有对话框唤起的输入法
  才会让辅助键盘让位收起。

## B. 自定义键（步骤序列）

> 打开方式：点 ⌨ → 点绿色「＋」→ 对话框（标签 + 步骤列表）。
> 每步一行 = 模式下拉（文本/^X/ESC/字节/回车/延迟）+ 内容输入框 + 「×」删除；
> 「＋ 步骤」追加。填完点「确定」。

### B5 六种模式逐个验证
每建一个键测一项：

| # | 模式 | 填法 | 预期 |
|---|---|---|---|
| 1 | 文本 | 内容 `date` | 按下 → 终端出现 `date` |
| 2 | ^X | 内容 `L` | 按下 → 清屏（^L） |
| 3 | ESC | 内容 `[H` | 按下 → 光标到终端左上角 |
| 4 | 字节 | 内容 `7f` | 按下 → 删除光标前一字符（DEL） |
| 5 | 回车 | 无内容（输入框隐藏） | 按下 → 执行当前行 |
| 6 | 延迟 | 内容 `500` | 单独延迟无观察点，放到 B6 里测 |

- **预期**：五个键全部按预期；标签自动生成（`date`、`^L`、`[H`、`0x7f`、`↵`）。
- **2026-11-18 扩展**：^X 模式现接受标点 `@ [ ] ^ _ ?` 与空格（`]` 发 ^]、
  `[` 发 ESC、`?` 发 DEL、空格发 NUL），测试项见 D 节。

### B6 宏（步骤序列 + 延迟节拍）
- **宏 1（清行并执行）**：
  1. ＋ → 标签留空 → 步骤1 模式 ^X 内容 `U`；
  2. ＋ 步骤 → 模式 文本 内容 `ls -la`；
  3. ＋ 步骤 → 模式 回车 → 确定；
  4. 终端先随便输一行乱字符，按该键 → **预期**：乱字符被清掉、`ls -la` 直接执行。
- **宏 2（等上条跑完再执行）**：
  1. ＋ → 步骤1 文本 `sleep 2`、步骤2 回车、步骤3 延迟 `2500`、
     步骤4 文本 `echo done`、步骤5 回车 → 确定；
  2. 终端下按该键 → **预期**：约 2.5 秒后出现 `done`（不是立刻、也不是永不）。

### B7 同内容双键各自编辑（索引定位修复验证点）⚠️ 重点
- **步骤**：
  1. ＋ → 步骤1 文本 内容 `aaa` → 确定（得到键 `aaa`）；
  2. 再加一个完全相同的 `aaa` 键 → 键盘上出现两个 `aaa`；
  3. **长按第二个 `aaa`**（右数第一个）→ 进编辑对话框；
  4. 把内容改为 `bbb` → 确定。
- **预期**：第一个仍是 `aaa`，只有第二个变成 `bbb`。
  （修复前：内容匹配定位，改的永远是第一个。）

### B8 删除与提示
- **步骤**：
  1. 长按任意**默认键**（如 `^A`）→ 弹确认框，文案含「可恢复」；
  2. 点删除 → 键消失；
  3. 长按**自定义键**（如 `bbb`）→ 直接进编辑对话框（无确认框）；
  4. 对话框内步骤行「×」可删步骤，但至少保留一步（最后一步删不掉）。
- **预期**：如上。

### B9 恢复默认键集
- **步骤**：
  1. 承接 B8：确认 `^A` 已删、`aaa`/`bbb` 等自定义键存在；
  2. **长按绿色「＋」** → 确认框「恢复默认键集」→ 点「恢复」。
- **预期**：`^A` 找回、全部自定义键清空、键集回到出厂 31 键。
  （菜单入口同款：长按 ⌨ → 「辅助键盘：恢复默认键集」。）

### B10 标签
- **步骤**：
  1. ＋ → 步骤1 ^X 内容 `U`、步骤2 回车 → 标签留空 → 确定；
  2. 再各建一个：字节 `1b`、延迟 `500`，标签都留空。
- **预期**：自动标签 `^U↵`、`0x1b`、`⏱500`；手填超长标签（>12 字符）被截断不撑破键。

## C. 布局与环境

### C11 横竖屏行高
- **步骤**：辅助键盘展开 → 转横屏 → 再转回竖屏。
- **预期**：行高随屏变（竖 34dp / 横 27dp），无整行被裁、无键点不到。
- **AI 实测（2026-11-17，Note 9）**：✓ 竖屏键高 33.8dp、横屏 26.9dp
  （uiautomator dump 实量）；kbd 容器竖屏 588px / 横屏 474px，全部行
  都在屏内（`dumpsys activity top` 核实）。注意 uiautomator 对
  ScrollView 内按键报的 bounds 不准，横屏量行高以 dumpsys 为准。

### C12 输入法让位
- **步骤**：辅助键盘展开 → 点终端唤输入法 → 收输入法。
- **实际行为（实测确认）**：⌨ 与系统输入法是**组合共存**——所有键盘
  都收起时点一次 ⌨，辅助键盘与输入法一同出现（一步就绪）；之后各自
  独立收起互不影响（点终端=输入法开/关，点 ⌨=辅助键盘开/关）。输入法
  收起后终端恢复、无残留黑边。
- **预期**：同上（v1 时代的「自动让位」规则已废弃，见 A4）。

### C13 键多时的布局（已实现：行数上限 + 竖向滚动）
- **实现（2026-11-17）**：自定义键**数量不设上限**；菜单「设置 → 辅助
  键盘行数」可选 2–6 行或不限（默认 4 行）。超过上限时只有可自定义区
  竖向滚动（固定区 HOME…INS / F1–F12 与键条不动，终端不被顶走）；
  「＋」恒在键集末尾，滚到底可达；新添加的键自动滚到底部可见。改动
  即时生效，无需重启。
- **AI 实测（Note 9）**：✓ 上限 2 行时 kbd 高度 392px（2 固定 + 2 自定义），
  上滑滚到底后 ＋ 键可见；改回 4 行即时恢复 588px；KbdTest 新增 6 例
  纯函数回归。
- **步骤（复测建议）**：菜单改上限为 2 → 辅助键盘变矮 → 在自定义区
  上下滑 → 再改回 4。
- **预期**：变矮/恢复即时；滚动只发生在自定义区；＋键滚动可达。

## D. vim 交互（输入组合边界）

> 前置：容器内装 vim（`apt install vim`，ubuntu 镜像）或用任意有 vim 的
> 环境；vim 无需配置，报错本身就是观察点。

### D0 边界声明（先读这个，分清「该测」与「勿测」）

**已实现，可测：**
1. **主键盘组合**：软键盘 CTRL 锁 + 主键盘（输入法）任意字符——`@` 到
   `_` 区间按 xterm 语义映射（字符 & 0x1f），含 `]`→^]；
2. **自定义键静态组合**：^X 模式填标点——`@`=NUL、`[`=ESC、`]`=^]、
   `^`=^^、`_`=0x1F、`?`=DEL（特例）、空格=NUL；
3. **键条方向键组合**：CTRL/ALT 锁 + 键条 ←↑↓→，vim 内按词跳。

**待实现边界（测了必失败，勿当 bug 报）：**
1. **软键盘按键动态消费粘滞 Ctrl/Alt**——如「键条 CTRL + 自定义文本键
   `ls`」。取舍：自定义键 = 字节直发（Termux extra-keys 同思路），动态
   修饰会把文本宏搅成控制字节（`ls`→`^L^S`）破坏宏确定性；需要组合时
   把字节静态写进键（^X/ESC/字节模式）。若未来实现，需先有「哪些键
   处于组合态」的视觉提示，届时再列测试项；
2. **^X 模式的数字与 `-`**：Ctrl+2=NUL、Ctrl+-=0x1F 是终端方言映射，
   各实现不一致，暂不猜；收下会静默发错字节，故保护性拒绝
   （非 ASCII 字母同理）。

### D1 Ctrl+] tag 跳转（主键盘组合）⚠️ 重点
- **步骤**：vim 打开任意文件进普通模式 → 软键盘 CTRL 锁上 → 主键盘敲 `]`。
- **预期**：vim 弹「E433: No tags file」或「E426: tag not found: …」——
  报错即证明 ^](0x1d) 已送达（建好 tags 文件则直接跳转）。
- **修复前现象**：无任何反应。

### D2 ^] 自定义键 tag 跳转 ⚠️ 重点
- **步骤**：＋ → ^X 内容 `]` → 确定（自动标签 `^]`）→ vim 普通模式按键。
- **预期**：同 D1。
- **AI 实测（2026-11-18，Note 9，字节级）**：✓ `cat -v` 下按 `^]` 键
  回显并输出 `^]`（0x1d）；`^@` 键输出 `^@`（0x00）；`^?` 键走行规程
  擦除（DEL 语义正确，会擦掉前一次回显——这是预期行为不是 bug）。

### D3 vim 行编辑基本盘（回归）
| # | 操作 | 预期 |
|---|---|---|
| 1 | 普通模式按默认键 `^R` | 命令行出现搜索提示 `:` 后接反向搜索 |
| 2 | 插入模式按默认键 `^U` | 清空当前行输入 |
| 3 | 插入模式按默认键 `^W` | 删除光标前一个词 |
| 4 | 任意模式按默认键 `^L` | 重绘屏幕（乱屏恢复） |
| 5 | 键条 ESC 或自定义 ESC 键 | 从插入模式退回普通模式 |
| 6 | CTRL 锁 + 键条 → / ← | 插入模式内按词右跳/左跳 |
| 7 | `:wq` 后按键条/自定义回车 | 保存退出（CR 语义，不是 ^J） |

> **用户实测（2026-11-18，Note 9）**：D0 待实现项按声明未测（正确）；
> D1/D2/D3/D4/D5 整体通过。D3.1 状态栏回显与最新实现一致；
> D3.2 插入模式下文本按普通文本插入正常。
>
> **观察点（非 bug）**：普通模式 / 插入模式 / `:` 命令模式之间没有明显
> 视觉反馈——这是 **vim 自身**的行为：默认只有插入模式在命令行左下角
> 显示 `-- INSERT --`（`showmode` 默认开），普通模式按设计不显示任何
> 指示器，`:` 模式的视觉特征就是底部命令行本身。与终端实现无关；
> 想要常驻模式指示属 vimrc 配置范畴（`showmode`/`statusline`），app
> 不代劳。

### D4 中文 composing（vim 插入模式）
- **步骤**：vim `i` 进插入模式 → 输入法敲中文 → 上屏。
- **预期**：候选上屏进 buffer，无丢字/重复。英文逐字还是先组待选区，
  由**输入法配置**决定（搜狗英文输入分**字母模式**=逐字上屏与**单词
  模式**=组词待选），与机型无关——两台设备行为不同时先核对输入法的
  英文模式设置是否一致。

### D5 粘贴多行（括号粘贴）
- **步骤**：vim 普通模式 → 终端长按粘贴若干行代码。
- **预期**：开启括号粘贴时整段原样进 buffer（不逐行执行、缩进不叠罗汉）。

## E. 文本选区（AI 实机已测，2026-11-19，M2010J19SC）

AI 已用 adb 全流程实测（选区手势在触屏上难以人工单手复现的场景，
用 `input motionevent` 精确注入），以下为实测记录；人为手感（长按触发
时机、自动滚动跟手度）留给用户复核：

### E1 长按起选 + 拖动扩展 + 浮动条 ✅
- 长按 "30" 行拖到 "33" 行：高亮 30–33，终点行按列收在 "33" 两字符；
  浮动条「复制 / 全选 / 取消」出现在顶部。

### E2 复制 ✅（双重验证）
- 点「复制」toast「已复制 12 个字符」= "30\n31\n32\n33\n" 恰 12 字符；
- 第三方印证：搜狗输入法剪贴板栏显示「来自剪贴板 30 31 32 33」。
- 全选后复制 160 字符（全部 scrollback + 屏幕），量级正确。

### E3 全选 / 取消 ✅
- 「全选」高亮覆盖 scrollback 顶到提示符的全部行；
- 「取消」高亮与浮动条同时消失。

### E4 scrollback 选区 + 顶边自动滚动 ✅
- 上滑查看历史（胶囊「↓ 8 行」）后长按 scrollback 行拖动：锚点全局

- 手指停在上边缘 2.5 秒：胶囊 8→23（滚到 scrollback 顶），选区端点
  固定、起点跟随视口延伸（xterm 拖出窗口自动滚同款语义）。

### E5 单击清选区、不弹键盘 ✅
- 选区存在时单击终端空白：高亮消失、软键盘不弹、滚动位置保留。

### E6 vim `mouse=a` 程序优先 ✅
- vimrc 写入 `set mouse=a` 后启动 vim，长按终端**不进入本地选区**
  （无高亮无浮动条），触摸按 mouse 报告交给 vim；
- 拖动 = mouse drag 上报，vim 进入 `-- VISU1 --`（Visual 选择）。
- 注意：应用菜单**不在**终端长按上（入口 = 长按键条「⌨」或顶栏「⋮」），
  鼠标模式下终端长按无本地动作。

### E7 Shift 直通（未测，需硬件键盘）
- 鼠标上报模式下 Shift+按下/拖动走本地选区（xterm shift override）。
  adb 无法模拟带 META_SHIFT 的触摸事件，留待接硬件键盘时测：

### E8 用户复核项（手感类）

## F. OSC 52 写剪贴板（AI 实机已测，2026-11-19，M2010J19SC）

前置：prefs 注入 `osc52`（菜单「设置 → 程序写剪贴板」是同一开关）。
写入命令用脚本绕开 `input text` 不能注入引号/冒号的限制：

```sh
printf '\033]52;c;'$(printf hello52 | base64)'\007'
```

## G. 外接键盘键位（AI 实测，2026-11-20，M2010J19SC）

`--es keytest "..."` 走 `dispatchKeyEvent`，用于回归应用侧的键位翻译（无实体键盘可回归）。
onNewIntent 热交付也已生效（本次顺手补的：原先只在冷启动触发）。
**但注入不能当作硬件键的替身**：`dispatchKeyEvent`/`input keyevent` 的事件来自虚拟键盘
（`deviceId=-1`），输入法对它的接管判断与真实蓝牙键盘不同，涉及输入法行为的项目
（组词、候选、选词上屏）必须用 `tools/hardkey.c` 的 uinput 真实设备路径，见 G2 与 G3。

### G1 已实测 ✅
- `ctrl+space` → `cat -v` 下见 `^@`（0x00；屏幕双显是 tty 规范模式的
  echo + cat 输出，一次字节两处显示）；随后 `ctrl+c` → `^C` + 提示符恢复。
- `shift+pgup` → 恰好回滚一页（13 行，胶囊「↓ 13 行」出现）；
  `shift+pgdn` → 回到底部。初版方向写反（PgUp 应 +scrollOffset），实测抓出已修。
- `ctrl+shift+a` → 全选高亮 + 浮动条。
- `shift+insert` → 粘贴（剪贴板内容为先前 Ctrl+Shift+C 复制的选区，多行确认框
  弹出、确认后逐行执行——粘贴链路 + 括号粘贴守卫全通）。
- 长按拖选 → 在选区下方长按拖动 = 下端点下移（扩大）；顶部附近长按拖动 =
  上端点收进（缩小）。见 H 节。

### G2 外接键盘中文输入（AI 实机复测，2026-11-20 晚，改用真实设备事件）
**本节早先「输入法对硬件键天生不组词、应用侧无解」的结论已作废**：那条对照实验
用的是 `adb shell input keyevent`，事件来自虚拟键盘（`deviceId=-1`），搜狗对它的
处理与真实蓝牙键盘不同，因此「搜索框也不组词」是假对照。真实按键要用
`tools/hardkey.c`（uinput 造 `bustype=BLUETOOTH` 设备，走 InputReader 真实设备路径）：

```bash
$NDK/toolchains/llvm/prebuilt/windows-x86_64/bin/aarch64-linux-android21-clang \
    -O2 -Wall -o .shot/hardkey tools/hardkey.c
adb push .shot/hardkey /data/local/tmp/ && adb shell chmod 755 /data/local/tmp/hardkey
adb shell /data/local/tmp/hardkey --settle 800 --gap 55 n i h a o space   # 组合键写 ctrl c
adb shell am start -n dev.dualterm.debug/dev.dualterm.MainActivity --ei chunklog 400  # 逐字节取证
adb shell dumpsys input_method | grep -iE "haveComposingNative|mInputViewStarted"
```

实测矩阵（搜狗小米版 + 工装真实按键，同机同输入法）：

| 输入区 `inputType` | 硬键盘 `nihao` | `Enter` | 备注 |
|---|---|---|---|
| `TYPE_NULL`（出厂） | 直发 5 个字母，`haveComposingNative:false` | 执行 | 回车后报 `nihao: not found` |
| `TYPE_NULL` + `show_ime_with_hard_keyboard=1` | 同上，仍不组词 | 执行 | `mInputViewStarted=true` 也救不了，症结在「非文本框」不在视图 |
| `TYPE_CLASS_TEXT`（临时改一行验证） | **组词**，空格选词 → PTY 逐字节 `out#12: 你好` | **被输入法吞掉，命令不执行** | 候选栏不可见时残留拼音会串味：上条命令没选词的 `ls` 下次空格时以「老师」冒出来 |
| `TYPE_CLASS_TEXT` + `KEYCODE_ENTER` 进 `shouldBypassIme` | 组词 + 空格上屏照常 | 执行 | 未选词的拼音仍滞留，需要按 composing 状态决定让不让回车 |
| 对照：系统设置搜索框（本就是 `TYPE_CLASS_TEXT`） | 组词，候选栏「你好/你号/倪好」 | — | 证明硬键盘组词能力在输入法侧一直存在 |

- 出厂版可用通路（已实测）：`show_ime_with_hard_keyboard=1` → 终端底部出现输入法条 →
  点 ⌄ 展开软键盘 → 硬键盘敲命令、软键盘点拼音 → 选词上屏，PTY 逐字节收到
  `out#39/40: 欧格/佐尼`；
- 软键盘触摸输入本身不受影响：拼音 → 选词 → `commitText` → PTY。
- **上表是「直接把那一行改成 `TYPE_CLASS_TEXT`」的对照实验，不代表出厂行为**：
  接管落地后回车的归属改成输入法仲裁（空闲退回 `\r`、挂拼音时把拼音原样上屏），
  逐条实测见 G3。

### G3 输入法接管落地后的实机验证（AI 实测，2026-11-20 晚，搜狗 + uinput 工装）

代码从 `TYPE_NULL` 改成「外接键盘 + 输入法界面可见 → `TYPE_CLASS_TEXT`」之后，
用 `tools/ime-check.sh` 逐条复测（它会 force-stop、拉起 `cat`、点屏把输入法叫出来，
确认 `mInputShown=true` 再注入序列）。下表取证跑在**临时插桩的构建**上（`pty.write` /
`ime.commit` / `takeover.probe` 三条诊断日志），出厂前这些日志已全删；出厂包的证据通道
是 `--ei chunklog 400` 的 `out#N`（PTY 实际收到的输出块），`ime-check.sh` 现在就走这条，
最后两行是在出厂包上重跑的。

```bash
# 编译工装（组合键用 # token，停顿用 :毫秒；--stdin 让设备常驻，否则每次注入
# 重建键盘会把输入法会话一起重建）
$NDK/toolchains/llvm/prebuilt/windows-x86_64/bin/aarch64-linux-android21-clang \
    -O2 -Wall -o .shot/hardkey tools/hardkey.c
$ADB push .shot/hardkey /data/local/tmp/ && $ADB shell chmod 755 /data/local/tmp/hardkey
bash tools/ime-check.sh 'enter' 'n i h a o :800 enter' 'space' 'n i h a o :800 esc :800 space'
```

| 场景 | 注入 | 实测 |
|---|---|---|
| 接管态空闲按回车 | `enter` | `pty.write [\r]`——输入法不消费、经 `sendKeyEvent` 退回，命令照常执行 |
| **挂着拼音按回车** | `n i h a o` `enter` | `ime.commit [nihao]` → `pty.write [nihao]`，**无 `\r`**：拼音原样上屏、不带 CR 把命令执行掉（旧行为的串味问题根除） |
| 接管态空闲按空格 | `space` | `pty.write [ ]` 直发 |
| 挂着拼音按退格 | `n i h a o backspace space` | 上屏「你哈」——退格删的是拼音尾字母而非命令行字符 |
| 挂着拼音按 Esc | `n i h a o esc space` | `pty.write [\e]` 之后 `ime.commit [你好]`：ESC 退给应用送达 PTY，但组词不取消（vim 用法上的坑，见 usage「中文等输入方案」） |
| 接管态空闲的终端语义键 | `tab up down left right home end pgup pgdn ins del esc enter` | `\t` `\e[A` `\e[B` `\e[D` `\e[C` `\e[H` `\e[F` `\e[5~` `\e[6~` `\e[2~` `\e[3~` `\e` `\r` 逐条照发，无一被吞 |
| 接管态的修饰组合 | `ctrl c` `ctrl d` | 两个控制字节都写进 PTY（日志里显示为空串即 0x03/0x04），组词期间也能中断 |
| 双击 Shift 切英文 | `shift :100 shift` 后接 `n i h a o space` | `takeover.probe … insetsShown=false` → 字母逐条 `pty.write [n][i][h][a][o]` 直发 |
| 再双击切回中文 | `shift :100 shift` 后接 `z h o n g space` | `ime.commit [中]` → `pty.write [中]` |
| 连打大写不误切 | `shift h :60 shift a space enter` | 上屏「哈」+ `pty.write [\r]`——中间插过字母，双击判定不成立 |
| 间隔过长不误切 | `shift :400 shift` 后接 `n i h a o space` | 仍组词出「你好」——两次按下相隔超出 500ms 窗口 |
| 「始终」档不受窗口门槛限制 | prefs `hw_ime=1`、不点屏 | `n i h a o space` → `pty.write [你好]`，随后 `enter` → `pty.write [\r]` |
| 「从不」档字母直发 | prefs `hw_ime=2` | `pty.write [n][i][h][a][o]` 逐条直发；双击 Shift 不生效（不越过用户策略） |
| 中文端到端 | 切英文打 `cat` 回车 → 切回中文 → `nihao` `zhong` 空格 | 屏上 `你好中`（tty echo + cat 双显），日志已全删的出厂包上验证 |
| 拔键盘回归 | 工装进程退出（uinput 设备销毁） | 辅助键盘重新出现、软键盘触摸输入组词照常 |
| **出厂包重跑：组词上屏** | `ime-check.sh 'n i h a o :800 space'` | `out#4: 你好`——`ime-check.sh` 现只走 `out#` 这一条证据通道 |
| **出厂包重跑：双击切英文** | 同上一条 + `shift :100 shift` 后 `e c h o space h i enter` | 字母逐块 `out#6`…`out#11` 直发、`echo` 被执行（行首还挂着上条未回车的「你好」，故报 `你好echo: not found`） |

### G4 仍需真实键盘的用户复核项
- 其它输入法（百度/Gboard）的实体键盘行为是否与搜狗一致——尤其**是否老实上报
  `setComposingText`**：Gboard 报了就会额外走 `imeComposing` 让路分支，搜狗全程不报
  也不影响（仲裁已不依赖它），但「回车交给输入法」在别的输入法上是否退得干净要实测；
- 候选栏画在输入法自己的窗口里（不占 IME inset）的输入法，自动档可能判成「不可见」
  → 不接管，需要用户选「始终」；
- 菜单「设置 → 外接键盘中文输入」三档切换后即时生效（`restartInput` 是否把所有
  输入法都拉回新语义）；
- 搜狗自带的硬键盘输入方案（如硬键盘中英切换、剪贴板粘贴）是否能满足实际打字；
- 菜单「屏幕内容」→「切换输入法…」弹系统选择器、选中另一个已启用的 IME 后
  输入立刻跟随；「输入法设置…」跳系统启用页；
- AltGr 字符（欧洲布局 `€` 等）与 Ctrl 组合叠加是否正确。
